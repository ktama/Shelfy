# データ形式と移行

## 1. この文書の位置づけ

現行の保存形式、再作成後の保存形式、両者をつなぐ交換形式を定義し、既存利用者のデータを失わずに移行する手順を示す。

扱う形式は 3 つある。

- **現行の保存形式**：SQLite データベース（`shelfy.db`）
- **交換形式**：エクスポートとインポートで使う JSON。現行と再作成後で共通にする
- **再作成後の保存形式**：JSON スナップショット（`shelfy.json`）

交換形式を現行と揃えるのは、これが移行の橋渡しになるからである。

## 2. 現行の保存形式

`%LOCALAPPDATA%\Shelfy\shelfy.db` に SQLite で保存する。
外部キー制約を有効化し、ジャーナルモードは WAL である。

### 2.1 Shelves テーブル

| 列          | 型      | 制約                                              |
| ----------- | ------- | ------------------------------------------------- |
| `Id`        | TEXT    | 主キー。GUID の文字列表現                         |
| `Name`      | TEXT    | NOT NULL                                          |
| `ParentId`  | TEXT    | NULL 可。`Shelves(Id)` への外部キー、削除時は連鎖 |
| `SortOrder` | INTEGER | NOT NULL、既定 0                                  |
| `IsPinned`  | INTEGER | NOT NULL、既定 0                                  |

### 2.2 Items テーブル

| 列               | 型      | 制約                                               |
| ---------------- | ------- | -------------------------------------------------- |
| `Id`             | TEXT    | 主キー。GUID の文字列表現                          |
| `ShelfId`        | TEXT    | NOT NULL。`Shelves(Id)` への外部キー、削除時は連鎖 |
| `Type`           | INTEGER | NOT NULL。0=File、1=Folder、2=Url                  |
| `Target`         | TEXT    | NOT NULL                                           |
| `DisplayName`    | TEXT    | NOT NULL                                           |
| `Memo`           | TEXT    | NULL 可                                            |
| `SortOrder`      | INTEGER | NOT NULL、既定 0                                   |
| `CreatedAt`      | TEXT    | NOT NULL。往復可能書式（`O`）の日時文字列          |
| `LastAccessedAt` | TEXT    | NULL 可。同上                                      |

### 2.3 Settings テーブル

| 列      | 型   | 制約     |
| ------- | ---- | -------- |
| `Key`   | TEXT | 主キー   |
| `Value` | TEXT | NOT NULL |

### 2.4 索引とスキーマ版数

索引は `Shelves(ParentId)`、`Items(ShelfId)`、`Items(DisplayName)`、`Items(Target)` に張られている。
スキーマ版数は `PRAGMA user_version` で管理し、現在は 1 である。

## 3. 交換形式（エクスポートとインポート）

キー名はローワーキャメルケース、値が未設定の項目は出力から省く。
日時は往復可能な ISO 8601 書式で表す。

```json
{
  "version": "1.0",
  "exportedAt": "2026-02-20T03:04:05.6789012Z",
  "shelves": [
    {
      "id": "9f1c2d3e-4a5b-6c7d-8e9f-0a1b2c3d4e5f",
      "name": "仕事",
      "parentId": null,
      "sortOrder": 0,
      "isPinned": true
    }
  ],
  "items": [
    {
      "id": "1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d",
      "shelfId": "9f1c2d3e-4a5b-6c7d-8e9f-0a1b2c3d4e5f",
      "type": 0,
      "target": "C:\\work\\report.xlsx",
      "displayName": "report.xlsx",
      "memo": "月次",
      "sortOrder": 3,
      "createdAt": "2026-01-05T12:00:00.0000000Z",
      "lastAccessedAt": "2026-02-19T09:30:00.0000000Z"
    }
  ]
}
```

| 項目                     | 型          | 必須 | 備考                              |
| ------------------------ | ----------- | ---- | --------------------------------- |
| `version`                | 文字列      | 必須 | 現在は `"1.0"`                    |
| `exportedAt`             | 日時        | 必須 | 出力時刻（UTC）                   |
| `shelves[].id`           | GUID 文字列 | 必須 |                                   |
| `shelves[].name`         | 文字列      | 必須 | 空文字は不可                      |
| `shelves[].parentId`     | GUID 文字列 | 任意 | 未設定はルート直下                |
| `shelves[].sortOrder`    | 整数        | 必須 |                                   |
| `shelves[].isPinned`     | 真偽値      | 必須 |                                   |
| `items[].id`             | GUID 文字列 | 必須 |                                   |
| `items[].shelfId`        | GUID 文字列 | 必須 | 同じファイル内の Shelf を指すこと |
| `items[].type`           | 整数        | 必須 | 0=File、1=Folder、2=Url           |
| `items[].target`         | 文字列      | 必須 | 空文字は不可                      |
| `items[].displayName`    | 文字列      | 必須 | 空文字は不可                      |
| `items[].memo`           | 文字列      | 任意 |                                   |
| `items[].sortOrder`      | 整数        | 必須 |                                   |
| `items[].createdAt`      | 日時文字列  | 必須 |                                   |
| `items[].lastAccessedAt` | 日時文字列  | 任意 | 未設定なら最近一覧に出ない        |

この形式は現行版と再作成後で同一に保つ。
現行版が書き出したファイルを再作成後が読め、その逆も成り立つことが、移行の前提になる。

### 3.1 取り込み時の検査

取り込みでは次の順に検査し、条件を満たさないレコードは飛ばす。
飛ばした件数は結果に含める。

1. 所属先の Shelf が存在しない Item を飛ばす
2. `type` が 0、1、2 のいずれでもない Item を飛ばす
3. 既に同じ識別子を持つレコードは取り込まない
4. 同一 Shelf 内で種別と参照先が重複する Item を飛ばす（[02-SPECIFICATION.md](02-SPECIFICATION.md) 第 12 節の 1 番）
5. 日時が解析できないレコードを飛ばす（同 2 番）

Shelf は親が先に取り込まれるように並べ替えてから処理する。
ファイル内での並び順に依存しない。

## 4. 再作成後の保存形式

`%LOCALAPPDATA%\Shelfy\shelfy.json` に、全データを 1 個のスナップショットとして保存する。

```json
{
  "schemaVersion": 1,
  "savedAt": "2026-02-20T03:04:05.6789012Z",
  "shelves": [ ... ],
  "items": [ ... ],
  "settings": {
    "GlobalHotkey": "Ctrl+Shift+Space",
    "WindowWidth": "800",
    "WindowHeight": "500",
    "StartMinimized": "false",
    "RecentItemsCount": "20"
  }
}
```

`shelves` と `items` の要素は、交換形式と同じ構造とする。
交換形式との違いは 3 点だけである。

- `version`（文字列）ではなく `schemaVersion`（整数）を持つ
- `exportedAt` の代わりに `savedAt` を持つ
- `settings` を含む

構造をそろえるのは、エクスポートを保存ファイルからの射影として実装できるようにするためである。

設定は文字列のキーと値で保持する。
値の解釈は読み手側の責任とし、解析できない値は既定値で置き換える。

`schemaVersion` は将来の形式変更に備えて置く。
読み込み時に自分が知る版数より大きい値を見つけた場合、上書き保存を行わずに読み取り専用として扱い、利用者に更新を促す。
新しい版のアプリが書いたデータを、古い版が壊すのを防ぐためである。

## 5. 移行手順

### 5.1 推奨手順（利用者が行う）

1. 現行版の Shelfy を起動する
2. エクスポートを実行し、JSON ファイルを保存する
3. 現行版を終了する
4. 再作成版を起動する
5. インポートを実行し、保存した JSON を「全置換」で取り込む
6. Shelf の階層、並び順、ピン留め、メモが再現されていることを確認する

この手順は、現行版と再作成版のどちらにも移行専用のコードを必要としない。
既にある機能だけで完結する。

### 5.2 現行版を起動できない場合

現行版が動かせない環境のために、一度きりの変換ツールを用意する。

- Rust の小さなコマンドとして `tools/shelfy-migrate` に置き、配布物には含めない
- `shelfy.db` を読み、交換形式の JSON を書き出す
- SQLite への依存はこのツールだけが持つ（`rusqlite` を使う）

このツールを本体から切り離すのは、再作成版の実行ファイルに SQLite を再び持ち込まないためである。
現行版の配布物では、SQLite のネイティブライブラリだけで 1.68 MiB を占めていた。
目標が単一 exe 10 MB 以下であることを踏まえると、移行のためだけにこれを常時抱えるのは割に合わない。

### 5.3 移行後の扱い

- 旧 `shelfy.db` は削除せず、そのまま残す
- 再作成版は `shelfy.db` を読まない
- 移行が完了したかどうかの判断は利用者に委ね、アプリが自動で削除や変換を行わない

自動変換を行わないのは、変換の失敗が利用者の唯一のデータに及ぶ経路を作らないためである。

## 6. 移行の検証

移行が正しく行われたことを、次の観点で確認する。

| 観点     | 確認内容                                                                     |
| -------- | ---------------------------------------------------------------------------- |
| 件数     | Shelf 数と Item 数が移行前後で一致する                                       |
| 階層     | 親子関係が移行前と同じ                                                       |
| 並び順   | 各階層、各 Shelf 内の表示順が移行前と同じ                                    |
| ピン留め | ピン留めされた Shelf が移行前と同じ                                          |
| メモ     | メモの内容が欠落していない                                                   |
| 日時     | 作成日時と最終アクセス日時が保たれ、最近一覧の順序が変わらない               |
| 識別子   | Shelf と Item の識別子が変わっていない                                       |
| 設定     | ホットキー、ウィンドウサイズ、起動時の挙動、最近の表示件数が引き継がれている |

設定は交換形式に含まれないため、移行後に設定画面で設定し直す。
確認項目に含めるのは、引き継がれない項目があることを利用者に伝えるためである。
