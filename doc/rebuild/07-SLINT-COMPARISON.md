# Slint との比較（フェーズ 1 の追加検証）

## 1. 実施の理由

[06-PHASE1-RESULT.md](06-PHASE1-RESULT.md) で、Tauri v2 は配布サイズと速度の目標を大きく上回った一方、常駐メモリが目標に届かなかった。
同節で挙げた選択肢のうち「構成を変える（Rust と Slint）」を、見込みではなく実測で判断するため、同じ画面と同じ判定項目で Slint 版の試作を作った。

両方の試作は、画面の構成、項目数（Shelf 5 件、Item 300 件）、ビルド設定（`opt-level = "s"`、LTO、`codegen-units = 1`、`panic = "abort"`、`strip`）をそろえてある。

| 項目   | 内容                                                             |
| ------ | ---------------------------------------------------------------- |
| 実施日 | 2026-09-08                                                       |
| 環境   | Windows 11 Pro（build 26200）、x64                               |
| ツール | Rust 1.96.0（MSVC）、Slint 1.17.1、Tauri 2.11.5、Node.js 22.16.0 |

## 2. 実測の比較

| 指標                       | 現行 WPF                 | Tauri v2                    | Slint                   |
| -------------------------- | ------------------------ | --------------------------- | ----------------------- |
| 単一 exe                   | 182,347,711 B（174 MiB） | **3,225,600 B（3.08 MiB）** | 9,664,000 B（9.22 MiB） |
| zip 圧縮後                 | 69.7 MB                  | **1.26 MB**                 | 4.92 MB                 |
| プロセス数                 | 1                        | 7                           | **1**                   |
| ワーキングセット（非表示） | 未計測                   | 374.7 MB                    | **71.2 MB**             |
| プライベート WS（非表示）  | 未計測                   | 79.4 MB                     | **38.4 MB**             |
| コミット（非表示）         | 未計測                   | **120.9 MB**                | 207.0 MB                |
| 起動から表示まで           | 未計測                   | 310 ms（309〜342）          | **188 ms（187〜188）**  |
| ホットキーから表示まで     | 未計測                   | 13 ms                       | 13 ms                   |
| 非表示 90 秒の CPU 時間    | 未計測                   | +0.04 秒                    | +0.09 秒                |

起動時間は外部から測った値である。
プロセスを起動してから、対象のウィンドウが可視になるまでを 5 ms 間隔で監視し、3 回の中央値を採った。
アプリ自身に測らせた値は、Slint 側がイベントループ開始前で止まるため比較にならない（第 4.1 節）。

「プライベート WS」はタスクマネージャの「メモリ」列に相当する。
「ワーキングセット」には他の WebView2 アプリと共有するページが含まれるため、Tauri 側で大きく出る。

## 3. 判定項目に対する結果

| 判定項目                     | 目標          | Tauri v2           | Slint                 |
| ---------------------------- | ------------- | ------------------ | --------------------- |
| 単一 exe                     | 10 MB 以下    | 達成（3.08 MiB）   | 達成（9.22 MiB）      |
| 常駐メモリ                   | 150 MB 以下   | 指標により分かれる | どの指標でも達成      |
| 起動から表示                 | 1,000 ms 以下 | 達成               | 達成                  |
| ホットキーから表示           | 100 ms 以下   | 達成（13 ms）      | 達成（13 ms）         |
| ホットキーとトレイ           | 動作          | 確認済み           | 確認済み              |
| ウィンドウの移動             | 動作          | 確認済み           | 確認済み              |
| Mica とフォールバック        | 両方成立      | 確認済み           | 確認済み（第 4.1 節） |
| エクスプローラからのドロップ | パス取得      | 確認済み           | **不可**              |
| 日本語入力と変換候補         | 正しく出る    | 確認済み           | **不可**              |

常駐メモリの目標に対して、Slint はワーキングセット 71.2 MB、プライベート WS 38.4 MB のいずれでも収まる。
Tauri はプライベート WS の 79.4 MB なら収まるが、ワーキングセットの 374.7 MB では収まらない。

ただし数値の優劣は結論を左右しなかった。
手元での確認により、Slint 版は日本語入力とエクスプローラからのドロップのどちらも動かないことが分かった。
いずれも Shelfy の中核操作であり、この 2 点で Slint は判定を満たさない。

## 3.1 Slint が満たせなかった 2 点

**日本語入力ができない。** 検索欄に日本語を入力できなかった。
Slint の入力欄が Windows の入力方式エディタを有効にしていないことが原因と考えられる。
利用者が日本語で棚や項目を検索する以上、これは代替手段のない欠落である。

**エクスプローラからのドロップが効かない。** `DragAcceptFiles` と `WM_DROPFILES` による実装は動かなかった。
ウィンドウを提供している winit 側が既に OLE のドロップ受け口を登録しており、`WM_DROPFILES` が配送されないためと考えられる。
そうであれば、既存の登録を解除したうえで `IDropTarget` を自前で実装することになり、第 4.2 節で見積もった 60 行では収まらない。

どちらも推定を含む診断であり、時間をかければ回避できる可能性はある。
ただし、いずれも Tauri では追加の作り込みなしに動いている。
中核操作をネイティブ実装の作り込みに賭ける理由は見当たらない。

## 4. Slint 側で分かったこと

### 4.1 ネイティブハンドルはイベントループ開始後にしか取れない

`show()` を呼んだ直後にウィンドウハンドルを取ろうとすると取得できない。
Slint は winit のイベントループが動き出してから実際のウィンドウを作るためである。

そのため次の 3 つを、ループ開始後の一度きりのタイマーで仕込む必要がある。

- Mica の適用
- ファイルドロップの受け口
- 枠なしウィンドウの移動

この順序を誤ると、Mica もドロップも黙って効かないだけで、エラーは出ない。
実際、最初の試作ではこれを踏み、Mica が適用されなかった。

なお、`DwmExtendFrameIntoClientArea` を呼ぶと標準のウィンドウボタンが現れてしまう。
Mica を適用するだけなら不要で、呼ばない方がよい。

### 4.2 OS からのファイルドロップは自前で実装する

Slint には、エクスプローラからのドロップを受け取る仕組みがない。
ネイティブウィンドウをサブクラス化し、`DragAcceptFiles` と `WM_DROPFILES` を自前で処理した（約 60 行）。

この方式の制約を記しておく。

- ドラッグ中の視覚的な反応（どこに落ちるかの表示）は自前で作る必要がある
- 仮想ファイル（メールの添付や書庫の中身など、実体のパスを持たない対象）は受け取れない

Shelfy はエクスプローラ上の実ファイルとフォルダを対象とするため、実用上の支障は小さい。
より広く受けるなら `IDropTarget` の実装が要る。

### 4.3 枠なしウィンドウの移動も自前

タイトルバーを掴んで動かす操作は、`WM_NCHITTEST` に応答して実装した。
上端の帯を掴める領域として返すだけで、二重クリックによる最大化も付いてくる。

### 4.4 ホットキーとトレイのイベントはポーリングで拾う

`global-hotkey` と `tray-icon` はイベントをチャネルで渡す。
Slint のイベントループに橋渡しするため、40 ms 周期のタイマーで受け取った。

このため、非表示中の CPU 時間が Tauri の倍になっている（90 秒で 0.09 秒と 0.04 秒）。
どちらも実用上は無視できる水準だが、完全に 0 にはならない。

### 4.5 ライセンス

Slint は 3 つのライセンスから選べる。

| ライセンス           | 内容                                                                       |
| -------------------- | -------------------------------------------------------------------------- |
| GPL-3.0-only         | Shelfy 自体が GPL になる                                                   |
| **Royalty-free 2.0** | デスクトップアプリなら無償。条件は帰属表示                                 |
| Slint Software 3.0   | 有償                                                                       |
| （補助クレート）     | tray-icon、global-hotkey、window-vibrancy はいずれも MIT または Apache-2.0 |

Royalty-free 2.0 を選ぶ場合、次のどちらかを満たせばよい。

- アプリのメニューから開ける About 画面に `AboutSlint` ウィジェットを表示する
- 配布ページ（README など、バイナリを入手できるページ）に「Made with Slint」バッジを表示する

Shelfy は GitHub で配布しているため、後者で足りる。
自作コードの MIT ライセンスはそのまま維持できる。

制約として、Slint 単体の再配布と、組み込み機器での利用と、Slint の API をそのまま外部へ公開することが禁じられている。
Shelfy の用途はいずれにも当たらない。

## 5. 定性的な比較

| 観点               | Tauri v2                                  | Slint                                              |
| ------------------ | ----------------------------------------- | -------------------------------------------------- |
| 実行環境の前提     | WebView2 が必要                           | **不要**                                           |
| 見た目の作り方     | CSS で自由に組める                        | Slint 独自のマークアップと `fluent` スタイル       |
| 見た目の再現度     | 既存の HTML と CSS の知識がそのまま使える | 独自言語の学習が要る。細部は自前で組む             |
| 日本語入力         | Edge の入力処理をそのまま使える           | winit の入力処理に依存する（要確認）               |
| ネイティブ実装の量 | 権限の宣言のみ                            | ドロップ、ウィンドウ移動、Mica の 3 つを自前で書く |
| 一覧の並び替え     | HTML5 の仕組みが使えずポインタ実装が要る  | いずれにせよ自前実装                               |
| ライセンス         | MIT または Apache-2.0                     | 帰属表示が要る                                     |
| 依存の数           | Rust 側と npm 側の二本立て                | Rust だけ                                          |
| ビルド             | フロントエンドのビルドが挟まる            | `cargo build` のみ                                 |

## 6. 結論

**Tauri v2 で進める。**

数値の上では、常駐メモリは Slint が明確に優れていた。
それでも Slint を採らないのは、日本語入力とエクスプローラからのドロップという 2 つの中核操作が動かなかったからである（第 3.1 節）。
メモリの差は利用者の体験に間接的にしか効かないのに対し、この 2 点は毎日の操作そのものである。

この結果により、[06-PHASE1-RESULT.md](06-PHASE1-RESULT.md) 第 5 節に挙げた選択肢のうち「構成を変える」は閉じた。
残るのは、常駐メモリの目標をどう扱うかである（第 7 節）。

Tauri を採ることで確定する制約を再掲する。

- 実行環境に WebView2 を要求する
- プロセスが 7 個立ち、ワーキングセットの合計は 375 MB 前後になる

いずれも [01-STACK_REVIEW.md](01-STACK_REVIEW.md) 第 8 節で受け入れた代償の範囲にある。

## 7. 常駐メモリの目標の扱い

Slint という退避先が閉じた以上、目標値の側を実測に合わせて決め直す。

| 指標             | 実測（非表示） | 意味                                              |
| ---------------- | -------------- | ------------------------------------------------- |
| プライベート WS  | 79.4 MB        | タスクマネージャの「メモリ」列。Shelfy 固有の費用 |
| ワーキングセット | 374.7 MB       | 他の WebView2 アプリと共有するページを含む        |
| コミット         | 120.9 MB       | 確保した仮想メモリ                                |

**プライベート ワーキングセットを基準とし、100 MB 以内を目標とする。**
共有ページを Shelfy の費用として二重に数えないためであり、利用者がタスクマネージャで目にする値でもある。

ワーキングセットの合計は目標に用いないが、計測して記録する。
WebView2 の基礎費用が変わったときに気付けるようにするためである。

この決定は [02-SPECIFICATION.md](02-SPECIFICATION.md) 第 11 節に反映する。

## 8. 試作の扱い

Slint 版の試作は役目を終えた。
一時領域に置いてあり、リポジトリには含めていない。

Tauri 版の試作は、フェーズ 2 以降で画面の骨格を作るときの出発点として使える。
[06-PHASE1-RESULT.md](06-PHASE1-RESULT.md) 第 4 節に記した 5 つの知見は、そのまま実装の前提になる。
