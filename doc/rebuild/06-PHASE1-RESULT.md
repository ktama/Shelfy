## 3. 実測値

### 3.1 配布サイズ

| 対象                         | サイズ                            |
| ---------------------------- | --------------------------------- |
| 単一 exe                     | 3,225,600 バイト（3.08 MiB）      |
| zip 圧縮後                   | 1,322,175 バイト（1.26 MB）       |
| フロントエンド（埋め込み前） | 26,718 バイト（HTML、CSS、JS 計） |

現行版の 182,347,711 バイトに対して **約 56 分の 1** である。
zip では 69.7 MB が 1.26 MB になる。

フロントエンドが 27 KB に収まったのは、UI ライブラリもアイコンフォントも同梱していないためである。
Windows 11 標準の Segoe UI Variable と Segoe Fluent Icons をそのまま使い、Fluent 風の見た目は CSS だけで組んだ。

### 3.2 速度

| 区間                                       | 実測        | 目標          |
| ------------------------------------------ | ----------- | ------------- |
| プロセス起動からウィンドウ表示（内部計測） | 286〜293 ms | 1,000 ms 以下 |
| プロセス起動からウィンドウ出現（外部計測） | 186 ms      | 参考          |
| ホットキー受信から表示完了                 | **13 ms**   | 100 ms 以下   |

ホットキーからの表示が 13 ms で済むのは、ウィンドウを起動時に作り切って隠しておき、呼び出しでは表示状態を切り替えるだけにしているからである。
[03-ARCHITECTURE.md](03-ARCHITECTURE.md) 第 10 節の配分が狙いどおり働いた。

### 3.3 メモリ

プロセスは 7 個立つ（本体 1 個と WebView2 の 6 個）。

| 構成                 | 状態   | ワーキングセット | プライベート |
| -------------------- | ------ | ---------------- | ------------ |
| 既定の起動引数       | 表示中 | 439.3 MB         | 213.0 MB     |
| 既定の起動引数       | 非表示 | 440.7 MB         | 208.8 MB     |
| 削減用の起動引数あり | 表示中 | 370.7 MB         | 124.2 MB     |
| 削減用の起動引数あり | 非表示 | 377.7 MB         | 123.3 MB     |

削減用の起動引数として次を与えた。

```text
--disable-gpu --disable-gpu-compositing --renderer-process-limit=1
--js-flags=--max-old-space-size=64
--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection,Translate,BackForwardCache
```

効果はプライベートで 85 MB、ワーキングセットで 63 MB あった。
GPU 処理を無効にしても、この画面では描画の乱れや体感の遅さは出ていない。

分かったことが 2 つある。

第一に、**非表示にしてもメモリは減らない**。90 秒放置しても 1 MB も動かなかった。
ランチャーは大半の時間を非表示で過ごすため、この値がそのまま常駐の費用になる。

第二に、**ワーキングセットとプライベートで評価が分かれる**。
ワーキングセットには WebView2 の実行イメージなど、他の WebView2 アプリと共有するページが含まれる。
Shelfy 固有の費用に近いのはプライベートの 123 MB であり、この基準なら目標に収まる。
一方、タスクマネージャで利用者が目にするのはワーキングセット側の値である。

### 3.4 非表示中の CPU

90 秒の非表示で、7 プロセス合計の CPU 時間は 0.22 秒増えた。
おおよそ 0.24% にあたる。
目標の「0% と見なせる水準」には届いていないが、実用上の影響は小さい。

## 4. 実装で分かったこと

設計に反映すべき事実を 5 つ得た。

### 4.1 権限（capabilities）の宣言が要る

Tauri v2 は、フロントエンドが使える機能を `src-tauri/capabilities/` の宣言で制御する。
これを置かないと、`invoke` による自前コマンドの呼び出しは通るのに、**イベントの受信とドラッグアンドドロップの通知だけが黙って届かない**。

試作では最初にこれを踏み、ホットキーの計測値がフロントエンドに届かなかった。
例外も警告も出ないため、原因の特定に手間がかかる。

`core:default` と `core:event:default`、`core:webview:default` を宣言して解決した。
[03-ARCHITECTURE.md](03-ARCHITECTURE.md) 第 6 節に、IPC の設計と並べて記載する必要がある。

### 4.2 グローバルホットキーはプラグインが面倒を見る

ウィンドウの一覧を調べると、プロセスは次の隠しウィンドウを持っていた。

```text
tray_icon_app          トレイアイコン用
global_hotkey_app      ホットキー受信用
dev.shelfy.spike-sic   単一インスタンス用
```

`WM_HOTKEY` を受け取るためのメッセージ専用ウィンドウは、プラグインが作っている。
自前で用意する必要はない。
[03-ARCHITECTURE.md](03-ARCHITECTURE.md) 第 8.1 節の判断が裏付けられた。

### 4.3 ホットキーの自動確認には低水準の入力が要る

`SendKeys` で `Ctrl+Shift+Space` を送っても、グローバルホットキーは発火しなかった。
`keybd_event` で修飾キーとキーを個別に送ると発火した。

自動確認を組むときは後者を使う。

### 4.4 CSS の `hidden` 属性は `display` に負ける

`display: flex` を持つ要素に `hidden` 属性を付けても隠れない。
`[hidden] { display: none !important; }` を最初に置いておく。

試作では、ドロップ領域が常に表示される不具合として現れた。

### 4.5 トレイイベントの形

`TrayIconEvent::DoubleClick` は `button_state` を持たない。
`Click` と混同しやすい。

## 5. 未達項目の扱い

常駐メモリは、削減策を入れてもワーキングセットで 377.7 MB あり、目標の 150 MB に対して 2.5 倍である。
プライベートの 123.3 MB なら目標に収まるが、どちらを基準にするかは決めていない。

[01-STACK_REVIEW.md](01-STACK_REVIEW.md) 第 10 節では、この場合に方針を相談して決めることにしている。
選べる道を挙げる。

1. **目標をプライベート基準に改める**：Shelfy 固有の費用に近い値を採る。共有ページを二重に数えないという理屈は立つ。ワーキングセットは 378 MB のままである
2. **目標値そのものを引き上げる**：配布サイズを 56 分の 1 にした代償として、常駐メモリの増加を受け入れる
3. **さらに削減を試みる**：一覧の仮想化、フロントエンドの縮小などで積み増す。ただし今回の 7 プロセス構成が費用の大半であり、効果は限定的だと見込まれる
4. **構成を変える**：Rust と Slint に切り替える。配布サイズは 6〜15 MB に増えるが、常駐メモリは 30〜60 MB になる見込み

**決着（2026-09-08 追記）**：4 番を実測で検証した結果、Slint は日本語入力とエクスプローラからのドロップが動かず脱落した（[07-SLINT-COMPARISON.md](07-SLINT-COMPARISON.md)）。
残った選択肢のうち 1 番を採り、目標をプライベート ワーキングセットで 100 MB 以内に改めた。
実測は 79.4 MB である。

3 番の効果が小さいと見込む理由を述べる。
今回の試作はデータもロジックも持たない最小構成であり、それでも 123 MB のプライベートを使っている。
つまり計測値のほとんどは WebView2 の基礎費用であって、こちらのコードの作り方では動かせない。

比較のため、現行の WPF 版の常駐メモリは測っていない。
実行すると利用者の実データとホットキー登録に副作用が出るため見送った。
判断の材料に要るなら、フェーズ 0 として先に計測する。

## 6. 残る手動確認

自動化できない項目が 3 つ残っている。
試作は起動したままにしてあるので、手元で確認できる。

| # | 確認すること                                                   | 手順                                                   |
| - | -------------------------------------------------------------- | ------------------------------------------------------ |
| 1 | 検索ボックスで日本語を入力でき、変換候補が入力位置に出る       | ウィンドウ上部の検索欄に「けんさく」と入力して変換する |
| 2 | エクスプローラからファイルを落とすと、一覧の先頭にパスが加わる | エクスプローラからウィンドウへファイルをドラッグする   |
| 3 | トレイの二重クリックで表示、右クリックのメニューで表示と終了   | 通知領域の Shelfy アイコンを操作する                   |

あわせて次も確認できる。

- `Ctrl+Shift+Space` で表示と非表示が切り替わる
- 一覧の行をドラッグして並び替えられる（ポインタイベントでの実装）
- ウィンドウの右上の最小化と、`Esc` での非表示

試作の終了はトレイメニューの「終了」から行う。
