# 再作成ドキュメント

Shelfy を軽量化と高速化の観点で作り直すための一式である。
現行実装の仕様を引き継ぎつつ、技術スタックを全面的に入れ替えることを目的とする。

## 結論

v1.0.0 のリリース資産は単一 exe で 174 MiB（zip で 69.7 MB）あった。
このうち約 165 MiB は .NET ランタイムと WPF 本体であり、自作コードは 300 KiB 弱にすぎない。
配布サイズの重さは、書いたコードではなくランタイムの同梱に由来する。

そこで **Rust と Tauri v2** で全面的に作り直した。
描画は OS に既にある WebView2 に任せ、実行ファイルには自分のコードだけを載せる。

**作り直しは完了した（2026-09-11）。** 目標をすべて満たしている。

| 指標               | 目標          | 実測     |
| ------------------ | ------------- | -------- |
| 単一 exe           | 10 MB 以下    | 3.46 MiB |
| zip                | 5 MB 以下     | 1.45 MB  |
| 起動から表示       | 1,000 ms 以下 | 310 ms   |
| ホットキーから表示 | 100 ms 以下   | 1.4 ms   |
| 1,000 件での検索   | 50 ms 以下    | 364 µs   |
| 常駐メモリ         | 100 MB 以下   | 80.8 MB  |

段階ごとの記録は [05-REBUILD_PLAN.md](05-REBUILD_PLAN.md) の各フェーズにある。

Fluent と Mica の見た目は、UI ライブラリを足さずに CSS と Windows 11 標準のフォントで組む。
[UI_DESIGN.md](../UI_DESIGN.md) で作り込んだ体験は、この方針で引き継ぐ。

## 選定の条件と、受け入れたトレードオフ

選定は次の 4 条件で行った。

1. 配布サイズを最優先する
2. 単一の実行ファイルを置くだけで動く
3. Fluent と Mica の見た目を維持する
4. 既存の C# 資産は捨ててよい

その結果、2 つの代償を受け入れている。

**常駐メモリは現行より増える可能性がある。** WebView2 が独立したプロセス群として動くためで、150 MB 以下を目標に対策を設計へ織り込む。

**実行環境に WebView2 を要求する。** Windows 11 には標準搭載されている。無い環境では起動時に検出して案内する。

いずれも [01-STACK_REVIEW.md](01-STACK_REVIEW.md) 第 8 節に、判断の経緯とともに記録した。

## 前提

再作成にあたって次を前提に置いた。
前提が変われば 01 の決定を見直す。

- 対象は Windows のみで、他 OS への展開予定はない
- 主な対象は Windows 11。Windows 10 も動作対象に含める
- 想定データ量は Shelf 数百件、Item 数千件
- ネットワーク通信は行わない
- C# の実装は全面的に書き直す
