# 仕様

## 1. この文書の位置づけ

Shelfy の振る舞いを、実装に依存しない形で定義する。
Rust でも TypeScript でも、どの層に置くかを決めずに読める粒度で規則を確定させてある。

実装とこの文書が食い違う場合、この文書を正とする。
振る舞いを変えるときは、コードより先にここを直す。

設計上どう実現するかは [ARCHITECTURE.md](ARCHITECTURE.md)、データ形式は [DATA_MIGRATION.md](DATA_MIGRATION.md) に分けてある。

## 2. プロダクト定義

**Shelfy**：ファイル、フォルダ、URL への参照を「棚」に置いて整理し、グローバルホットキーで即座に呼び出して起動する常駐型ランチャーである。

設計の優先順位は次のとおりとする。

1. 呼び出しから起動までの体験
2. データの安全性（参照元の実体を決して変更しない）
3. 保守性
4. 見た目の完成度

守る原則を挙げる。

- タグによる分類を持たない（置き場所そのものが分類である）
- 参照先の実体を移動も変更もしない
- ネットワーク通信を行わない（ローカル完結）
- 常駐を前提とし、ウィンドウを閉じても終了しない

## 3. ドメインモデル

### 3.1 Shelf

参照を格納する論理的な棚である。

| 属性        | 型         | 必須 | 説明                           |
| ----------- | ---------- | ---- | ------------------------------ |
| `Id`        | 一意識別子 | 必須 | 生成後は不変                   |
| `Name`      | 文字列     | 必須 | 空文字と空白のみは不可         |
| `ParentId`  | 一意識別子 | 任意 | 未設定はルート直下を表す       |
| `SortOrder` | 整数       | 必須 | 同一階層内での表示順、既定値 0 |
| `IsPinned`  | 真偽値     | 必須 | ピン留め状態、既定値 false     |

不変条件を挙げる。

- `Name` は空文字にできない（生成時と改名時の両方で検査する）
- 自分自身を親にできない
- 自分の子孫を親にできない（循環の禁止）

### 3.2 Item

Shelf に属する参照である。

| 属性             | 型                      | 必須 | 説明                                       |
| ---------------- | ----------------------- | ---- | ------------------------------------------ |
| `Id`             | 一意識別子              | 必須 | 生成後は不変                               |
| `ShelfId`        | 一意識別子              | 必須 | 所属する Shelf、移動で変化する             |
| `Type`           | `File`、`Folder`、`Url` | 必須 | 生成後は不変                               |
| `Target`         | 文字列                  | 必須 | パスまたは URL、生成後は不変、空文字は不可 |
| `DisplayName`    | 文字列                  | 必須 | 空文字と空白のみは不可                     |
| `Memo`           | 文字列                  | 任意 | 未設定可                                   |
| `SortOrder`      | 整数                    | 必須 | 同一 Shelf 内での表示順、既定値 0          |
| `CreatedAt`      | 日時（UTC）             | 必須 | 生成後は不変                               |
| `LastAccessedAt` | 日時（UTC）             | 任意 | 起動に成功した時点で更新する               |

不変条件を挙げる。

- Item は必ず 1 つの Shelf に属する
- `Target` と `DisplayName` は空文字にできない
- 同一 Shelf 内で `Type` と `Target` の組が重複してはならない
- 重複判定は `Type` が `Url` のときだけ大文字小文字を区別し、`File` と `Folder` では区別しない
- 参照先の実体が存在するかどうかは状態として扱い、存在しないことを理由に Item を削除しない

`Type` を永続化形式に落とすときの数値は `File` = 0、`Folder` = 1、`Url` = 2 とする。
この対応は入出力ファイルの互換性に直結するため変更しない。

## 4. ユースケース

各ユースケースは、成功と失敗を区別できる結果を返す。
失敗の種別は呼び出し側が分岐できるように区別する（利用者へのメッセージを文字列比較で分岐させない）。

### 4.1 Shelf の操作

#### CreateShelf

入力は名前と親 Shelf（省略時はルート）である。

処理は次の順で行う。

1. 名前が空、または空白のみなら「入力エラー」で終える
2. 親が指定されていて存在しなければ「親が見つからない」で終える
3. 同一階層の兄弟を取得し、`SortOrder` を「兄弟の最大値 + 1」とする（兄弟がなければ 0）
4. Shelf を追加する

結果の種別は、成功、入力エラー、親が見つからない、の 3 つである。

#### RenameShelf

入力は Shelf と新しい名前である。
名前が空、または空白のみなら入力エラーとする。
対象が存在しなければ「見つからない」で終える。

#### MoveShelf

入力は Shelf と新しい親（未指定はルートへの移動）である。

1. 対象が存在しなければ「見つからない」で終える
2. 新しい親が自分自身なら「不正な移動」で終える
3. 新しい親が指定されていて存在しなければ「親が見つからない」で終える
4. 新しい親が自分の子孫なら「不正な移動」で終える
5. 親を付け替える

#### DeleteShelf

入力は Shelf である。
対象が存在しなければ「見つからない」で終える。
存在する場合、子 Shelf を深さ優先で再帰的に削除し、各 Shelf に属する Item をまとめて削除してから、Shelf 自身を削除する。

利用者に対しては、削除前に「配下ごと削除する」ことを明示した確認を求める。

#### TogglePinShelf

入力は Shelf である。
ピン留め状態を反転し、反転後の状態を結果に含める。

#### ReorderShelves

入力は、並び替え後の順に並んだ Shelf の識別子リストである。
先頭から順に `SortOrder` へ 0 から始まる連番を割り当てる。
リストが空なら何もせず成功とする。
リスト中に存在しない Shelf があれば「見つからない」で終える。

このユースケースは同一階層内の並び替えに使う。
階層をまたぐ移動は MoveShelf の役割である。

### 4.2 Item の操作

#### AddItem

入力は Shelf、種別、参照先、表示名、メモ（任意）である。

1. 参照先が空、または表示名が空なら入力エラーで終える
2. Shelf が存在しなければ「Shelf が見つからない」で終える
3. 同一 Shelf 内に同じ種別かつ同じ参照先の Item があれば「重複」で終える（比較規則は 3.2 に従う）
4. `SortOrder` を「同一 Shelf 内の最大値 + 1」とする（Item がなければ 0）
5. `CreatedAt` に現在時刻（UTC）を設定して追加する

#### RemoveItem

入力は Item である。
参照だけを削除し、参照先の実体には触れない。
対象が存在しなければ「見つからない」で終える。

#### RenameItem

入力は Item と新しい表示名である。
空、または空白のみなら入力エラーとする。

#### UpdateItemMemo

入力は Item とメモである。
メモは未設定にもできる。

#### MoveItemToShelf

入力は Item と移動先 Shelf である。

1. Item が存在しなければ「見つからない」で終える
2. 移動先 Shelf が存在しなければ「Shelf が見つからない」で終える
3. 移動先に同じ種別かつ同じ参照先の別 Item があれば「重複」で終える
4. `SortOrder` を移動先の「最大値 + 1」に付け替え、所属 Shelf を変更する

#### ReorderItems

入力は、並び替え後の順に並んだ Item の識別子リストである。
規則は ReorderShelves と同じで、0 から始まる連番を割り当てる。

#### GetRecentItems

入力は取得件数（省略時は 20）である。
`LastAccessedAt` が設定されている Item だけを対象とし、降順に並べて先頭から指定件数を返す。
結果には Item が属する Shelf の名前を添える。
Shelf 名が解決できない場合は `Unknown` とする。

#### GetMissingItems

入力はない。
全 Item のうち、参照先が存在しないものを Shelf 名付きで返す。

存在確認の規則を定める。

- `http` または `https` の絶対 URL は、通信を行わず常に存在するものとして扱う
- それ以外は、ファイルまたはフォルダとして存在するかを調べる
- 空文字と空白のみは存在しないものとして扱う

### 4.3 起動

#### LaunchItem

入力は Item である。

1. Item が存在しなければ「見つからない」で終える
2. 参照先を OS の既定の関連付けで開く
3. 開けなければ「起動失敗」で終える
4. 成功したら `LastAccessedAt` に現在時刻（UTC）を記録する
5. 起動後の画面制御を決めて結果に含める

起動後の画面制御は次の規則で決める。

- ホットキーの修飾キーが押されたままなら、ウィンドウを表示したままにする
- そうでなければウィンドウを非表示にする

この判断はユースケースの責務であり、UI 側で決めない。
連続して複数の Item を起動したい場合に、修飾キーを押したまま操作を続けられるようにするための規則である。

#### OpenParentFolder

入力は Item である。

1. Item が存在しなければ「見つからない」で終える
2. 種別が `Url` なら「非対応」で終える
3. 参照先を選択した状態でエクスプローラを開く
4. 親フォルダが特定できない、または存在しない場合は「失敗」で終える

### 4.4 データ入出力

Export と Import の詳細は [DATA_MIGRATION.md](DATA_MIGRATION.md) に置く。
ここでは振る舞いだけを述べる。

#### ExportData

全 Shelf と全 Item を、書式バージョンと出力時刻を添えた 1 個の構造にまとめて返す。
保存先のファイルは利用者が選ぶ。
既定のファイル名は `shelfy_export_<yyyyMMdd_HHmmss>.json` とする。

#### ImportData

入力は取り込むデータと、全置換かマージかの指定である。

全置換の場合は、既存の Item と Shelf を全て削除してから取り込む。

取り込みは次の順で行う。

1. Shelf を、親が先になるように並べ替えて取り込む
2. 既に同じ識別子の Shelf があれば取り込まずに次へ進む
3. Item は、所属先 Shelf が存在しないものを飛ばす
4. 種別の数値が定義域外のものを飛ばす
5. 既に同じ識別子の Item があれば取り込まずに次へ進む
6. 同一 Shelf 内で参照が重複する Item を飛ばす
7. 日時の解析に失敗したレコードは、そのレコードだけを飛ばす

7 番で処理全体を中断しないのは、1 件の壊れたレコードのために残り全部が入らない事態を避けるためである。

結果には、取り込んだ Shelf 数と Item 数を含める。
飛ばしたレコードがある場合は、その件数も含める。

## 5. 検索

### 5.1 クエリの構文

検索文字列は空白で区切ったトークン列として解釈する。
各トークンは、既知のプレフィックスを持つ場合は絞り込み条件、持たない場合はフリーテキストとして扱う。

| プレフィックス | 意味                        | 一致規則                                                                 |
| -------------- | --------------------------- | ------------------------------------------------------------------------ |
| `box:`         | Shelf 名で絞り込む          | 部分一致、大文字小文字を区別しない                                       |
| `type:`        | 種別で絞り込む              | `file`、`folder`、`url` のいずれかと完全一致（大文字小文字を区別しない） |
| `in:`          | 指定した Shelf 内に限定する | 名前の完全一致、大文字小文字を区別しない                                 |

同じプレフィックスが複数回現れた場合、最後の指定が有効になる。
プレフィックスの後ろが空のトークン（`box:` だけなど）は、条件として扱わずに無視する。
`type:` の値が既知の 3 種以外だった場合、その条件は絞り込みに使わない。

フリーテキストのトークンは半角空白 1 個で連結し、1 個の文字列として扱う。

### 5.2 一致の規則

フリーテキストは次のいずれかに部分一致すれば該当とする（大文字小文字を区別しない）。

- Item の表示名
- Item の参照先（パスまたは URL）
- Item のメモ
- Item が属する Shelf の名前

Shelf 名に一致した場合は、その Shelf に属する全ての Item を結果に含める。
Shelf 名だけで棚ごと引き当てられるようにするための規則である。

フリーテキストの照合では、`%` や `_` のようなパターン文字も普通の文字として扱う。

絞り込み条件（`box:`、`type:`、`in:`）は、フリーテキストの結果に対して全て満たす形（論理積）で適用する。

### 5.3 空クエリの扱い

フリーテキストと 3 種の絞り込みが全て空なら、結果は空とする。

フリーテキストが空で絞り込みだけがある場合（`type:url` だけなど）は、全 Item を対象に絞り込みを適用する。

### 5.4 応答

検索は入力のたびに実行する。
連続入力に対しては待ち時間を挟んでから実行し、途中で入力が変わったら前の実行を取り消す。
待ち時間は 100 ms とする。
検索は全件をメモリ上で走査するだけで済むため、この長さでも入力に追従できる。

## 6. 常駐と呼び出し

### 6.1 常駐

- 起動するとトレイに常駐する
- ウィンドウを閉じる操作は終了ではなく非表示とする
- 終了はトレイメニューからのみ行う
- 多重起動を抑止する。既に起動している場合は、既存プロセスのウィンドウを表示して新しいプロセスは終了する

多重起動を抑止するのは、データファイルの同時書き込みと、グローバルホットキー登録の衝突を防ぐためである。

### 6.2 グローバルホットキー

- 既定は `Ctrl+Shift+Space`
- 押下時、ウィンドウが表示されていれば非表示にし、非表示であれば表示して前面に出し、フォーカスを与える
- ホットキーは設定で変更でき、変更は再起動を待たずに反映する
- 登録に失敗した場合（他のアプリが同じ組み合わせを使っている場合など）、その旨を利用者に知らせる。アプリは終了せず、トレイからの呼び出しで使えるままにする

ホットキー文字列は `修飾キー+修飾キー+キー` の形式とする。
修飾キーとして `Ctrl`、`Shift`、`Alt`、`Win` を解釈する。
解析に失敗した場合は既定値を用いる。

### 6.3 トレイ

- 二重クリックでウィンドウを表示する
- 右クリックメニューに「表示」と「終了」を置く
- ツールチップにアプリ名と現在のホットキーを表示する

## 7. 画面と表示規則

### 7.1 画面構成

1 枚のウィンドウを、左の Shelf ツリーと右の Item 一覧に分ける。
上部に検索入力を置き、下部に操作結果を示す領域を置く。

### 7.2 表示モード

一覧領域は 4 つのモードを持つ。

| モード | 表示内容                | 遷移のきっかけ                       |
| ------ | ----------------------- | ------------------------------------ |
| 通常   | 選択中 Shelf の Item    | Shelf を選択する、検索入力を空にする |
| 検索   | 検索結果                | 検索入力に文字がある                 |
| 最近   | 最近起動した Item       | 「最近」を選ぶ                       |
| 欠損   | 参照先が存在しない Item | 「欠損」を選ぶ                       |

検索、最近、欠損のモードでは、各 Item がどの Shelf にあるかを併記する。

通常モード以外で Shelf を選択した場合、通常モードに戻して選択した Shelf の内容を表示する。
選択だけが変わって一覧が変わらないと、操作の結果を予測できないためである。

### 7.3 並び順

Shelf ツリーは、同一階層内で次の優先順に並べる。

1. ピン留めされているものが先
2. `SortOrder` の昇順
3. 名前の昇順

Item 一覧は、通常モードでは `SortOrder` の昇順、次に表示名の昇順で並べる。
最近モードでは最終アクセス日時の降順で並べる。
検索モードと欠損モードでは、Shelf ごとにまとまる順序であればよい。

### 7.4 Item の表示項目

1 件につき、種別を表すアイコン、表示名、参照先、メモ、最終アクセス日時を表示する。
参照先が存在しない Item には警告の印を付ける。

### 7.5 存在確認の実行方法

存在確認は UI スレッドで同期実行しない。
一覧を表示したあとに背景で実行し、判明した順に表示へ反映する。
同じ参照先に対する確認結果は短時間（30 秒）だけ再利用してよい。

一覧の要素を作るたびに同期でファイル I/O を行うと、切断されたネットワークドライブを含む一覧で操作全体が止まる。
表示を先に出し、確認は後から追いつかせる。

## 8. 設定

| 設定キー           | 内容                         | 既定値                           |
| ------------------ | ---------------------------- | -------------------------------- |
| `GlobalHotkey`     | グローバルホットキー         | `Ctrl+Shift+Space`               |
| `WindowWidth`      | ウィンドウ幅                 | 800                              |
| `WindowHeight`     | ウィンドウ高さ               | 500                              |
| `StartMinimized`   | 起動時にウィンドウを出さない | false（`"true"` のときだけ有効） |
| `RecentItemsCount` | 最近モードの表示件数         | 20                               |

設定はキーと値の文字列として保持する。
値が解析できない場合は既定値を用い、エラーにしない。

保存の規則を定める。

- 設定画面で保存した内容は、ウィンドウサイズとホットキーを含めて即座に反映する
- ウィンドウを非表示にするとき、そのときのサイズを保存する（最大化中や最小化中は保存しない）

## 9. 操作

### 9.1 キーボード

| キー               | 操作                                 |
| ------------------ | ------------------------------------ |
| `Ctrl+Shift+Space` | 表示と非表示の切り替え（グローバル） |
| `Ctrl+N`           | 新規 Shelf 作成                      |
| `Enter`            | 選択中 Item の起動                   |
| `F2`               | 選択中 Item の名前変更               |
| `Delete`           | 選択中 Item の削除                   |
| `Ctrl+R`           | 再読み込み                           |
| `Escape`           | ウィンドウを非表示にする             |

### 9.2 マウス

- Item の二重クリックで起動する
- Shelf と Item の右クリックで、それぞれに対する操作メニューを出す
- Shelf のメニューには、新規作成、子の作成、ピン留めの切り替え、移動、上下移動、名前変更、削除を置く
- Item のメニューには、起動、親フォルダを開く、名前変更、メモ編集、別の Shelf へ移動、上下移動、削除を置く

### 9.3 ドラッグアンドドロップ

- エクスプローラからウィンドウへのドロップで、選択中 Shelf に Item を追加する
- Item 一覧内のドラッグで並び替える
- Shelf ツリー内のドラッグで並び替える

追加時の種別判定は次の順で行う。

1. `http` または `https` の絶対 URL なら `Url`
2. フォルダとして存在するなら `Folder`
3. それ以外は `File`

表示名の既定値は、ファイルとフォルダではパスの末尾要素、URL ではホスト名とする。

Shelf が選択されていない状態でのドロップは、追加先が決まらないため何もしない。
その旨を利用者に伝える。

### 9.4 URL の追加

URL は、参照先と表示名を順に入力して追加する。
`http` と `https` 以外のスキーム、および絶対 URL でない入力は受け付けない。

## 10. 利用者への通知

操作の結果は、成功と失敗の別が分かる形で画面に示す。
文言は次の方針で組み立てる。

- 何に対する操作かを含める（対象の表示名を入れる）
- 失敗時は、何が起きたかを利用者の語彙で述べる（内部の型名や例外メッセージをそのまま出さない）
- 破壊的操作（Shelf の削除、全置換インポート）は、実行前に確認を求める

## 11. 非機能要件

| 項目                 | 要件                                                          |
| -------------------- | ------------------------------------------------------------- |
| 実行環境             | Windows 10 以降、x64                                          |
| 導入                 | 単一の実行ファイルを置くだけで動く。インストーラを要さない    |
| 実行環境の前提       | WebView2 ランタイム。無い場合は起動時に検出して案内する       |
| 通信                 | 行わない                                                      |
| データの保存先       | `%LOCALAPPDATA%\Shelfy`                                       |
| 想定データ量         | Shelf 数百件、Item 数千件                                     |
| 起動からトレイ常駐   | 1,000 ms 以内                                                 |
| ホットキーから表示   | 100 ms 以内                                                   |
| 1,000 件での検索応答 | 50 ms 以内                                                    |
| 常駐時のメモリ       | 関連プロセス合計のプライベート ワーキングセットで 100 MB 以内 |
| 非表示中の CPU       | 0% と見なせる水準                                             |
| 配布サイズ           | 単一 exe 10 MB 以下                                           |
| 異常終了時のデータ   | 直前の保存内容を失わない                                      |
| ログ                 | `%LOCALAPPDATA%\Shelfy\Shelfy.log` に追記する                 |

未捕捉の例外はログに記録し、アプリを落とさずに操作を続けられる状態を保つ。

常駐時のメモリが 60〜90 MB 規模の WPF 実装より増えうることは、配布サイズを最優先した判断の代償として受け入れている。
描画を WebView2 に任せる以上、独立したプロセス群の分は避けられない。

指標にプライベート ワーキングセットを採るのは、複数プロセスが共有するページを Shelfy の費用として二重に数えないためである。
ワーキングセットの合計は目標に用いないが、計測して記録する。

非表示中に CPU を使わないという要件は、この構成では明示的な作り込みを要する。
ウィンドウが隠れているあいだ、描画、アニメーション、定期処理を止める。

### 11.1 実測

| 項目                 | 要件          | 実測（2026-09-10）           |
| -------------------- | ------------- | ---------------------------- |
| 配布サイズ           | 10 MB 以下    | 3,628,544 バイト（3.46 MiB） |
| 配布アセット（zip）  | 5 MB 以下     | 1,523,549 バイト（1.45 MB）  |
| 起動からトレイ常駐   | 1,000 ms 以内 | 中央値 310 ms、最大 452 ms   |
| ホットキーから表示   | 100 ms 以内   | 中央値 1.4 ms、最大 3 ms     |
| 1,000 件での検索応答 | 50 ms 以内    | 364 µs                       |
| 常駐時のメモリ       | 100 MB 以内   | プライベート WS 80.8 MB      |
| 非表示中の CPU       | 0% と見なせる | 90 秒で 0.094 秒（0.10%）    |

非表示中の CPU だけは 0 にならない。
内訳を見ると自前のコードは 0.000 秒で、残りは WebView2 自身の背景動作である。

計測の手順は [DEVELOPMENT.md](DEVELOPMENT.md) 第 5 節にある。
依存を足したときに配布サイズが静かに戻らないよう、上限はリリースの手順でも検査している。

## 12. v1.0.0 からの挙動の違い

v1.0.0（C# と WPF と SQLite）からデータを移してくる利用者のために、
同じ操作で結果が変わる箇所を挙げる。

| # | 箇所           | v1.0.0 の振る舞い                           | 現在                                       | 理由                                       |
| - | -------------- | ------------------------------------------- | ------------------------------------------ | ------------------------------------------ |
| 1 | Import         | 同一 Shelf 内の参照重複を検査しない         | 重複するレコードを飛ばす                   | ドメイン規則に違反したデータが入るのを防ぐ |
| 2 | Import         | 日時の解析に失敗すると処理全体を中断する    | 該当レコードだけを飛ばし、件数を報告する   | 1 件の不正で全件が入らないのを避ける       |
| 3 | 存在確認       | 一覧要素の生成時に同期でファイル I/O を行う | 背景で実行し、結果を短時間キャッシュする   | 一覧表示が参照先の応答に引きずられる       |
| 4 | 検索の待ち時間 | 300 ms                                      | 100 ms                                     | メモリ内検索になり実行が軽くなる           |
| 5 | 表示モード     | 検索中に Shelf を選んでも一覧が変わらない   | 通常モードに戻して選択内容を表示する       | 操作結果が予測できない                     |
| 6 | 多重起動       | 抑止していない                              | 抑止し、既存プロセスのウィンドウを表示する | データ競合とホットキー登録の衝突を防ぐ     |
| 7 | 並び替えの保存 | 対象 1 件ごとに永続化する                   | 並び替え全体を 1 回の保存にまとめる        | 往復の削減                                 |

7 番は内部の話であり、利用者から見た振る舞いは変わらない。

設定は交換形式に含まれないため、移行後に設定し直す必要がある。
手順は [DATA_MIGRATION.md](DATA_MIGRATION.md) 第 5 節にある。
